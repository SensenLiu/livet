# 待决开放问题（Open Questions）

> 本文档记录策划阶段未拍板的开放问题。新 agent 在做产品/开发方案时**可以提出建议**，但**不要替用户做最终决定**。每个问题列出选项+各自利弊+我目前的倾向。

---

## Q1：品牌名

**候选**：

| 候选 | 含义 | 优点 | 缺点 |
|---|---|---|---|
| **「在场」** / Present / Live | AI 与你在场 | 简洁、有哲学感、易传播 | 略抽象 |
| **「Moment」** / 重要时刻 | 重要时刻在你身边 | 直白、和场景概念呼应 | 略普通 |
| **「Whisper」** / 私语 | 耳边的低声提示 | 形象、契合"被动提示" | 与 OpenAI Whisper 撞名 |
| **「拾光」** / Time Keeper | 拾起重要的瞬间 | 文艺、留存感 | 不够"工具" |
| **「Echo」** / 回声 | 回应你生活中的瞬间 | 简洁 | 与 Amazon Echo 撞名 |
| **「在耳」** / In Ear | 始终在耳边 | 直击形态 | 不够品牌感 |
| **「同行」** / Companion / With | 一生同行 | 契合"AI 拐杖一生陪伴"使命 | 略软 |
| **「AI 拐杖」**（保留） | 原始命名 | 直白、使命感强 | 对年轻人/职场场景违和 |

**我的倾向**：「在场」/「Moment」并列推荐。「在场」更哲学，「Moment」更直白。

## Q2：被动提示载体优先级

**候选**：
- A. 耳机骨传导提示音 优先
- B. 手机字幕弹屏 优先
- C. 智能手表/腕带震动 优先
- D. 三个并行（用户自配组合）

**关键考量**：
- 公开场合（开会、谈判）哪种最不被察觉？→ 耳机最强，但耳机戴着也是被察觉
- 文字提示是否比语音提示更"克制"？→ 是的，但需要看屏幕
- 不同人群偏好差异大？→ 老人偏好语音、白领偏好字幕

**需要做的事**：阶段 0 MVP 中三种都做，让用户自配，30 天后看真实使用数据。

## Q3：数据本地化的极限

**问题**：完全无云端可行吗？还是必须留极薄网关？

**当前方案**：极薄 BFF 网关（API key 代理 + 订阅校验 + 错误日志）

**完全无云端的挑战**：
- 大模型 API key 必须服务端持有（否则反编译 App 就泄露）
- 微信支付/Apple IAP 的回调验证需要服务器
- 这两点决定了至少要有最薄的网关

**结论**：当前的"极薄 BFF"已是最小方案，无需进一步缩减。但可以做"用户自带 key"模式作为高级选项（用户输入自己的 DeepSeek/OpenAI key，完全脱离我们的服务器）。

## Q4：🔴守护监听模式上线时机

**问题**：V2 还是 V3？

**两难**：
- 过早上隐私雷区高（24h 持续监听 vs 用户对隐私的真实焦虑）
- 过晚错失适老化人群（守护模式正是老人/独居/弱势人群的核心刚需）

**我的倾向**：V2 上线，但**默认关闭**，需要用户两次确认（风险告知+隐私协议）+ 提供更详细的隐私控制粒度（如关键词白名单、地理围栏限定家中开启等）。

## Q5：是否单独立"看病管家"子品牌

**问题**：阶段 1 数据出来后，如果 S1 看病场景跑出强 vertical 价值，要不要拆个独立品牌（如「医妈妈」/「孝心 AI」）？

**我的倾向**：先看数据再决定。如果 S1 转化率显著高于其他 → 拆独立品牌专攻适老化付费市场，主品牌保持通用。这是"双品牌战略"。

## Q6：第一个合伙人画像

**候选画像**：
- A. 渠道型合伙人（销售/BD/政府关系，能搞定保险/医院/社区）
- B. 技术型合伙人（端侧+大模型工程能力强，能补创始人不足）
- C. 产品型合伙人（懂适老化/B 端，做过 0-1 产品）
- D. 设计型合伙人（懂老人/弱势用户的交互设计）

**我的倾向**：根据创始人自身能力补短板。如果创始人是技术背景 → 优先 A 或 C；如果是产品背景 → 优先 B 或 A。

## Q7：海外路线

**问题**：阶段 0 同步埋一个英文版的种子吗？

**做的好处**：
- 同一套代码改 prompt + 翻译，边际成本低
- 海外用户付费意愿强，可能比国内先跑通商业模式
- Be My Eyes 等海外案例证明无障碍 AI 在海外有真需求

**做的代价**：
- 注意力分散
- 海外营销渠道完全不同（不会用抖音/小红书就难推）
- App Store 海外审核标准严

**我的倾向**：阶段 0 不做。但代码架构应支持多语言（i18n + prompt 模板化），阶段 1 末期视情况启动。

## Q8：大模型自研 vs 一直用 API

**当前方案**：DeepSeek API + 豆包 API 双供应商兜底

**长期需要小模型微调的能力**：
- "何时被动提示"判断（在端侧实时跑，必须小模型）
- "跨场景记忆"提取（频次极高，API 成本不堪）
- "对话上下文识别"（区分用户参与对话 vs 电视/广播）

**我的倾向**：阶段 0-1 全用 API；阶段 2 开始用 7B-8B 开源小模型微调（基于自己的真实数据）；阶段 3+ 视情况自研更小的端侧专用模型。

## Q9：数据使用边界承诺

**问题**：是否从 Day 1 就明确"不用用户数据训练大模型"作为差异化承诺？

**做的好处**：
- 强化"数据本地优先"品牌信任
- 可能是吸引高隐私敏感用户的杀手特性
- 与豆包/元宝等"用用户数据训练"的产品形成清晰差异

**做的代价**：
- 失去一个数据飞轮（其他厂商有，我们没有）
- 长期模型质量可能落后

**我的倾向**：**做这个承诺**。理由是：
1. 用户体验质量更多取决于"何时被动提示"和"跨场景记忆"两个端侧算法，而不是底层大模型本身
2. 这个承诺是"端为主架构"的逻辑延伸，能讲出独特的故事
3. 即使要用数据训练，也可以用"用户主动同意+完全脱敏+可撤回"的方式做
