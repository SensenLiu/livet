# 关键决策记录（Decisions Log）

> 本文档记录在策划讨论中已经做出的重要决策。**已决问题不应被新 agent 重新讨论**——除非用户主动要求重审。
> 每条决策包含：决策内容、反对意见/原方案、最终判断逻辑。

## D1：战略路径选 C（平台化+先切高付费 vertical），不选 A（适老化专攻）

- **最初提案（v1）**：切适老化作为唯一入口，"子女付费给老人"作为商业模式
- **反对意见**：
  - 个人探索阶段做适老化渠道太重（社区/医院/保险/微信），单干很难铺
  - 销售周期长（6 个月+）、决策链复杂
  - 单一场景叙事限制平台延展性
- **最终决策**：路径 C
  - 公司战略层：搭一个底层引擎，长期目标覆盖多 vertical
  - 产品落地层：第一年聚焦多场景通用 App 跑通，让用户行为告诉我们最值得深挖的 vertical
  - 使命层：心里的"AI 平权"是终极目标，但路一步步走——先用赚钱的 vertical 养活公司、磨利核心能力，最后回归弱势人群
- **判断逻辑**：A 路径 vs B 路径 vs C 路径中，C 路径既保留使命又规避了 A 的渠道难度

## D2：MVP = App + 蓝牙耳机，不选小程序，不自研硬件

- **最初提案（v1）**：微信小程序 + 公众号作为 MVP（成本 ¥3-5 万）
- **反对意见（用户提出）**：小程序/公众号承载不了"被动感知+主动提示+零门槛"这三个产品独特性，等于花 3 个月验证了一个错误的命题，本质上和现有豆包没区别
- **最终决策**：App + 通用蓝牙耳机
  - iOS + Android（React Native）
  - 兼容 AirPods / 华为 / 小米等通用蓝牙耳机
  - 不自研硬件
- **真实成本**：在 AI 编程时代 1.5-2.5 个月、1 个全栈工程师、¥8-12 万（端为主架构后）
- **3 个真实门槛**：
  1. 后台持续录音的合规雷区（iOS/Android 系统都对后台麦克风有限制，App Store 审核会卡）
  2. 持续录音的耗电（VAD 智能唤醒解决）
  3. "什么时候提示"的算法（这是真正的难点，而非技术能否实现）

## D3：去掉反诈作为独立场景包

- **最初提案（v2）**：8 场景包含 S7 反诈守护
- **反对意见（用户提出）**：国内反诈赛道是红海（国家反诈中心、腾讯反诈、运营商拦截、银行 App），且现有产品都不是 LLM 做的，是关键词+号码库；语义级反诈 LLM 能做但容易误报、与现有产品差异点小、品牌叙事不性感
- **最终决策**：场景包从 8 个减为 7 个，反诈作为底层"语义风险检测能力"在所有场景里默默兜底，不作为独立场景包对外推广

## D4：架构改为"端为主 + 极薄 BFF 网关"

- **最初提案（v2）**：阿里云后端 + Python FastAPI + PostgreSQL + Redis
- **反对意见（用户提出）**：仅做手机 Agent 直接调大模型行不行？为什么需要后端？
- **最终决策**：极薄 BFF 网关（~200 行 Python）只做 3 件事
  1. API key 代理（大模型/ASR 的 key 必须服务端持有）
  2. 订阅状态校验（微信支付/Apple IAP 验签）
  3. 匿名错误日志（可关）
- **不做**：用户数据存储、会话历史、复盘内容——全部默认本地
- **额外好处**：成本低（¥99/月轻量服）、隐私强、反 lock-in、把"我们看不到你的数据"变成杀手级营销点

## D5：交互模式从"主动建议/插话"改为"被动提示"

- **最初提案（v2）**：🟡 重要时刻模式 = AI 看到危险/孤独/有机会主动说话
- **反对意见（用户提出）**："插话"是错误的设计，AI 不该期待用户回复。理想是耳麦/HUD 式的提示，不打断节奏
- **最终决策**：三模式重新定义
  - 🟢 主动询问模式：用户问 → AI 答（类似豆包）
  - 🟡 **被动提示模式**（V1 核心）：耳机轻提示音 + 手机字幕弹屏，永不主动开口对话，永不期待回应
  - 🔴 守护监听模式（V2）：24h 被动监听，仅在求助/紧急/异常时联动子女/紧急联系人
- **品牌哲学层面**：派生出"派生准则 2"（被动提示，不期待回应）写进 Part 0 铁律

---

## D6：长期记忆引擎是核心 IP，用户永不重复说背景

- **最初提案（v2）**：S6 重要决策 = "把情况说一遍，AI 多角度分析"
- **反对意见（用户提出）**：违背产品愿景！产品就是让 AI 时刻融入人们的生活，避免用户对生活场景的会议和描述的麻烦操作
- **最终决策**：所有场景包重新设计，遵守"AI 自动调取记忆，用户只说当下"铁律
  - 例：S6 重要决策 → 用户只说"该不该接 A 公司 offer"，AI 自动检索目标/薪资/家庭/B 公司谈判进度
- **架构影响**：长期记忆引擎（Memory Engine）从"V2 才上"提升为"V1 必须有"的核心模块；写进核心 IP 文件清单（`memory-engine.ts`）
- **品牌哲学层面**：上升为 Part 0 铁律的灵魂——"让你不必再向 AI 解释你自己"

## D7：场景识别渐进自动化（V1 用户手动选 → V3 全自动）

- **最初提案（v2）**：V1 就让 Agent 根据语音自主选 skill
- **反对意见（我自己提的，用户认可）**：V1 直接上自动场景识别有 3 个风险
  1. 场景误判（正跟同事谈业务，AI 误判成"S5 情绪"开始安抚 → 灾难）
  2. 端侧推理不足（持续做"场景判断+skill 选择"需要 GPT-4o/Sonnet 4.5 级别模型）
  3. API 成本失控（持续 LLM 判断 = 持续烧钱）
- **最终决策**：V1 用户手动选 → V1.5 已选场景内自动切 skill → V2 默认全自动 → V3 24h 全局 Agent

## D8：合规与续航策略明确

- **决策**：
  - iOS 用 audio background mode + 前台服务通知（系统强制显示麦克风指示器）
  - Android 用前台 Service + 持续通知栏图标
  - **绝不**用 VoIP 框架伪装通话（灰色，未来可能被审核拒）
  - 端侧 VAD（Silero VAD/WebRTC VAD）极低功耗持续运行
  - 续航预期：iPhone 15 加 VAD 智能唤醒可达 10-14 小时

## D9：不直接做医患场景诊室录音

- **最初提案**：S1 看病管家 = 实时听诊+实时给患者提示
- **反对意见（用户提出）**：医患场景的法律灰色 + 医院/医生反感的 5 个真实原因（怕医闹/诊疗节奏被打断/保守医疗/其他病人隐私/医院院规）
- **最终决策**：S1 看病管家形态调整为「就医管家：看完病不慌、不忘药、不漏复查」
  - 不做诊室实时录音
  - 出诊室后用户对 AI 复述医嘱
  - 拍照上传处方/化验单/CT 报告
  - AI 综合解读+用药日历+复诊提醒+子女转发
  - "诊室内录音"留作高级权限选项，需用户主动开启并阅读合规承诺

## D10：首批 4 个场景包

- **决策**：阶段 0 MVP 先做 4 个场景
  - S1 看病管家
  - S2 重要谈话
  - S5 情绪急救
  - S8 日复盘
- **覆盖**：中老年/职场/通用三大类
- **理由**：合规风险低、覆盖广、能验证不同人群对"被动提示"形态的接受度

## D11：GTM = 7 组场景化短视频，不做通用叙事

- **决策**：通用 App 不能用通用叙事推广。**叙事按场景拆，产品按平台一体化**。
- **打法**：7 组短视频跑 3 个月，看哪个场景转化率最高、留存最好，下半年集中预算到 Top 2 场景
- **渠道映射**：
  - S1 看病 → 抖音/小红书孝心向
  - S2 谈话 → 知乎/B 站职场
  - S3 学习 → B 站学习 UP
  - S4 跨语言 → 小红书出差/留学
  - S5 情绪 → 小红书心理/治愈
  - S6 决策 → 即刻/小红书
  - S8 复盘 → 即刻/微博

## 已被否决但值得记录的方案

| 方案 | 被否原因 |
|---|---|
| 单一切适老化 vertical | 个人阶段渠道太重 |
| 微信小程序 MVP | 无法承载产品独特性 |
| 阿里云重型后端 | 不必要、增加成本和隐私焦虑 |
| AI 主动开口对话 | 违反"不期待回应"哲学 |
| "把情况说一遍"式 prompt | 违反"不必解释自己"哲学 |
| V1 直接 Agent 自动选场景 | 误判风险/端侧推理/成本失控 |
| 反诈作为独立场景包 | 红海且非 LLM 差异化 |
| 诊室实时录音翻译 | 法律灰色 + 医生反感 |
| VoIP 框架伪装通话做后台 | 合规灰色，未来被审核风险 |
| "AI 朋友/陪伴"叙事 | 海外 Humane/Friend 失败案例反复证伪 |
