# Part 0：产品哲学铁律

> **「让你不必再向 AI 解释你自己。」**

这是 Life Crutch（暂用此代号，最终命名待定）vs 现有 ChatGPT/豆包/元宝等所有 AI 助手产品的根本性差异，是一条贯穿所有功能、所有场景、所有交互的设计铁律。

任何产品决策、任何场景设计、任何技术取舍，都必须先回到这一条来判断"是否合规"。

---

## 派生准则（4 条）

### 1. AI 主动获取上下文，用户只说"当下"

**正确范式**：
- AI 已经听过你最近的对话、读过你最近的复盘、记住了你的偏好
- 用户做决策时只说"那个事我该怎么决定"
- AI 自动 RAG 检索相关历史上下文（最近事件、人物关系、目标、未决事项），多角度分析

**错误范式**（绝不允许）：
- "请详细描述你的情况" ❌
- "你能告诉我更多关于 A 公司的信息吗" ❌
- 任何要求用户重复交付背景的对话 ❌

**底层支撑**：长期记忆引擎（Memory Engine）—— 每次场景启用都生成结构化记忆（事件/人物/情绪/未决事项），每天复盘自动写入档案，跨场景可检索。

### 2. 被动提示，不期待回应

**正确形态**（类比：主播耳麦、棋牌提词、HUD 抬头显示）：
- 耳机骨传导轻提示音
- 手机字幕弹屏 / 锁屏推送
- 腕带/智能手表震动
- 用户可完全忽略，无尴尬、不打断对话节奏

**错误形态**（绝不允许）：
- AI 主动开口对话 ❌
- AI 期待用户回应 ❌
- AI 在用户跟他人讲话时插话 ❌

**底层支撑**：「何时被动提示」算法（hint-timing），是公司核心 IP 之一。提示错了用户忽略就行；插话错了用户会被尴尬死。

### 3. 数据本地优先，永不保留原声

**默认配置**：
- 所有用户数据存本地 SQLite
- 流式 ASR 转文字后立即销毁原声
- 云端只有极薄 BFF 网关（API key 代理 + 订阅校验 + 可关闭的匿名错误日志）
- 用户可一键删除/导出全部数据

**作为品牌承诺**（写进首屏 + 隐私协议 + 应用商店描述）：
- "永不保留原声"
- "数据本地优先"
- "我们看不到你的内容"

**例外**：多端同步/家庭共享是可选高级功能，且必须端到端加密。**绝不**用用户数据训练大模型（Day 1 起的承诺）。

### 4. 场景识别渐进自动化

**演进路线**（写进研发路线，不可跳跃）：

| 版本 | 用户体验 | 技术依赖 |
|---|---|---|
| **V1** | 用户手动选场景，一键启动 | 现有大模型 + prompt 工程 |
| **V1.5** | 已选场景内 Agent 自动切 skill（如看病模式下听到"挂号"自动切到"导诊 skill"）| Agent 框架 + 工具调用 |
| **V2** | 默认全自动，用户不再选场景，Agent 听一句话自己判断 | GPT-4o/Sonnet 4.5+ 级别模型 + 端侧推理优化 |
| **V3** | 跨场景 24h 全局 Agent，无需任何用户启动 | 自研轻硬件 + 微调小模型 |

**为什么不一上来就全自动**：场景误判风险极高（"S5 情绪"误判到正在跟同事谈业务的场景里 → 灾难）；端侧推理压力大；API 成本失控。必须有用户手动校准的过渡期。

---

## 这 4 条铁律的检查清单

设计任何新功能/新场景/新交互前，必须自问：

- [ ] 这个设计是否要求用户重复交付背景？如果是 → 违反准则 1，重新设计
- [ ] 这个交互是否让 AI 主动开口对话/期待用户回应？如果是 → 违反准则 2，改成被动提示
- [ ] 这个功能是否需要在云端存用户原始数据？如果是 → 违反准则 3，改为本地存或端到端加密
- [ ] 这个功能是否一上来就要求 Agent 全自动判断场景？如果是 → 违反准则 4，加入用户手动选项作为过渡

---

## 与产品名的呼应

无论最终选「在场」/「Moment」/「同行」哪个品牌名，产品 slogan 都应直接呼应这条铁律：

- 「在场」 → "AI 与你在场，不必解释"
- 「Moment」 → "重要时刻在场，不必重述"
- 「同行」 → "AI 与你同行，懂你不必说"
